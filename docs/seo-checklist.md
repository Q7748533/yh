# 内容与 SEO 标准（新文章一律按此执行）

**本文件是标准，不是建议。** 2026-10-24 对首篇文章做完整审计后确立，其中可机器校验的部分已写入 `scripts/qa.mjs`，`npm run build` 不通过即中断部署。

标注说明：**✅ 自动拦截** = 构建失败；**⚠️ 人工** = 发文前人工核对。

## 一、五条硬性红线（审计中发现并修复的问题）

| # | 规则 | 状态 |
|---|---|---|
| 1 | **禁止用单条编辑评分写 `aggregateRating`**。Google 要求聚合评分反映多条真实评分；单条只能写 `Product.review.reviewRating`（ratingCount=1 属违规标记） | ✅ 自动拦截 |
| 2 | **`og:image` 必须是 PNG/JPG/WEBP**，1200×630。SVG 在 Facebook/X/LinkedIn 不渲染，等于没有分享图 | ✅ 自动拦截 |
| 3 | **`<title>` ≤ 60 字符**（硬上限 65）。超长时省略站名后缀 | ✅ 自动拦截 |
| 4 | **文章页 `og:type` 必须是 `article`**，不是全站统一 `website` | ✅ 自动拦截 |
| 5 | **Pagefind 搜索资源不得首屏预加载**，必须点击后加载（约省 30KB 首屏） | ✅ 自动拦截 |

## 二、页面级标准

| 项 | 标准 | 状态 |
|---|---|---|
| `meta description` | 100–160 字符，含具体利益点，不堆关键词 | ✅ |
| H1 | 全页唯一，与 title 同主题 | ✅ |
| 标题层级 | 不跳级（H1 → H2 → H3） | ⚠️ |
| `canonical` | 自引用、绝对 URL、每页恰好 1 个 | ✅ |
| `html lang` | 存在且正确（`en`） | ✅ |
| 作者署名 | 可见 + 链接到 About（E-E-A-T） | ⚠️ |
| 更新日期 | 页面可见 + `dateModified` | ⚠️ |
| 自制图表 | 每篇至少 1 个 `figure`（数据图/对比表截图） | ✅ |
| 站内链接 | 至少 1 条向上（品类/品牌页）+ 1 条横向（相关测评），锚文本描述性 | ⚠️ |

## 三、结构化数据

| 规则 | 说明 |
|---|---|
| Review 必须挂在 Product 内 | 用 `Product.review`，不要孤立 `Review`（缺 `itemReviewed` 无富媒体资格） |
| Amazon 评分不进 schema | 页面可显示 "Amazon rating: 4.5/5 (reference only)"，schema 只写本站评分 |
| Offer 价格与页面一致 | `priceValidUntil` ≤ 价格抓取日 + 7 天 |
| FAQPage 只标记可见问答 | 注意 2023-08 起 FAQ 富媒体仅对政府/医疗类开放，保留 markup 是为 AI 搜索，不是为 SERP 折叠 |
| 无 AggregateRating | 见红线 #1 |

## 四、版式与转化标准（2026-10-24 布局审计后确立）

| 规则 | 状态 |
|---|---|
| **首屏决策卡**：评分 + 价格 + CTA + 披露 + 更新日合并为一张卡，移动端约 1 屏 | ✅ 自动拦截 |
| **区块顺序**：决策卡 → TL;DR → 优缺点 → 规格表 → 评分分解 → 正文 → 结论 → FAQ | ✅ 自动拦截 |
| **TL;DR 写在 frontmatter**（`tldr`，80–600 字符），由布局渲染在决策卡下方，不再写进正文 | ✅ schema 强制 |
| **规格表必须渲染**：`specs` 不得只存不显（曾出现 import 了组件但从未调用） | ✅ 自动拦截 |
| **评分分解**：`scoreBreakdown` 权重之和 = 1，加权结果 = rating（容差 0.06） | ✅ schema 强制 |
| **目录**：桌面右侧 sticky + 滚动高亮，移动端折叠 | ✅ 自动拦截 |
| **FAQ 折叠**：`<details>`，首条展开，内容仍在 HTML 中 | ✅ 自动拦截 |
| 正文行宽约 700px（`max-w-5xl` + 200px 目录列） | ⚠️ |
| 移动端表格不做横向滚动（规格表两列自适应；对比表给滑动提示） | ⚠️ |
| 移动端粘性购买条：滚过决策卡后出现，可关闭，本会话记住 | ✅ 渲染 |
| 每篇至少 2 张自制图（成本构成 + 评分/能力） | ⚠️ |
| **产品图**：`heroImage` 必填（厂商官方图或实拍），图下用 `imageCredit` 注明来源，alt 写描述性文本 | ⚠️ 人工 |
| **每篇独立 OG 图**：构建时由 `/og/<slug>.png` 自动生成（评分卡模板，1200×630） | ✅ 自动 |
| Product schema 的 `image` 指向产品图（无产品图时用评分卡） | ✅ 自动 |

## 五、反模板化 / 反规模滥用（2026-08 spam update 后确立，100 篇规模的前提）

**背景**：2026-08-18～21 Google spam update 明确打击 scaled content abuse，点名 "template-based programmatic pages" 与 "thin affiliate pages"。判定三条件：页面数量大、目的是操纵排名、没有为读者增加价值。

| 规则 | 状态 |
|---|---|
| **跨页重复句 = 0**：同一句话（≥10 词）不得出现在两篇文章正文里 | ✅ 构建拦截 |
| **正文 ≥ 500 词**（低于此判为薄内容） | ✅ 构建拦截 |
| **对比页发布闸门**：`/compare/` 只在 `src/data/compareNotes.ts` 登记了人工撰写的差异分析时才生成，否则不生成页面（避免 O(n²) 个模板页：100 篇同品类 = 4,950 页） | ✅ 构建拦截 |
| **品类页闸门**：品类内测评 < 3 篇时 noindex，且不用 "Best X" 表述 | ✅ 已实现 |
| **模板文字占比 < 20%**：评估方法、披露等段落必须每篇重写，不得复制 | ⚠️ 人工（重复句检测覆盖了主要风险） |
| **发布节奏**：每 10 篇为一批，观察 GSC 收录与展现 30 天后再放量；不批量上同构页 | ⚠️ 人工 |

> 判定原则：**读者看完这页，有没有获得"看前三个搜索结果拿不到的东西"？** 没有就不要发布。

## 六、内容质量（防薄内容 / scaled content abuse）

- [ ] 人工撰写的独特导语 ≥ 150 词，非模板拼接
- [ ] 至少 1 个独有数据点（自测结果或独家整理的数据）
- [ ] 至少 1 处与官方文案不同的判断（如成本测算、参数矛盾、口径差异）
- [ ] 无"仅换产品名"的模板页；产品数不足 3 个时不用 "Best X" 表述
- [ ] 结论来源已标注（`research` / `tested`），无伪装实测（"we tested" 表述）
- [ ] Amazon 评论仅作线索：不引原句、不成段改写、不署名、不用图；归纳须与规格表或第二信源交叉验证

## 七、技术层

- [ ] `sitemap-index.xml` 自动生成且包含新页
- [ ] `robots.txt` 声明 sitemap
- [ ] **站内链接全部可达**（QA 已加死链检查：导航/页脚/正文内链逐条比对 dist 文件——曾出现导航 "Best of" 指向不存在的 `/best/`）
- [ ] 404 返回 404 状态码
- [ ] 首屏无第三方阻塞脚本（Pagefind 已改点击后懒加载）
- [ ] 图片有 alt，或 SVG 有 `<title>` + figcaption
- [ ] 移动端可读（导航在 768px 以下独立横滑）

## 八、发布后
